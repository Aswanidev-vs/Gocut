# Fix: Images not rendering in exported video

## Root Cause

In `internal/render/queue.go:374-491`, the `buildSimpleFFmpegArgs()` function iterates over all tracks and clips. For each clip it:

1. Registers the input with FFmpeg (`-loop 1 -i <path>`) — this works for all track types including images
2. Builds a filter chain — **only for `TrackVideo` and `TrackAudio`**
3. **`TrackImage` and `TrackPIP` clips are registered as inputs but never connected to any filter chain**, so they are silently ignored by FFmpeg and don't appear in the output

The if-else at lines 407-488 handles `TrackVideo` and `TrackAudio` but has no branch for `TrackImage` or `TrackPIP`.

## Fix

**File**: `E:\Gocut\Gocut\internal\render\queue.go`

Add handling for `TrackImage` and `TrackPIP` in the same loop, between the `TrackVideo` block (line 407) and the `TrackAudio` block (line 464). The filter chain for image/PIP clips should be identical to the video clip chain (format, scale, pad, color, transform, opacity, transition, setpts) but **without** the audio processing section.

Specifically, add an `else if` for `track.Type == project.TrackImage || track.Type == project.TrackPIP` that:
- Creates the same filter chain as `TrackVideo` (lines 408-443)
- Adds the clip to `videoOverlays` for overlay compositing (line 443)
- Skips the audio embedding section (lines 445-462) since images have no audio
- Still increments `inputIdx` (line 489, already happens)
